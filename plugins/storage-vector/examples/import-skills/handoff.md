# 会话交接（Handoff）

**ID**: `handoff`

**版本**: 1.0.0

**描述**: 把当前会话压缩为交接文档，让一个干净上下文的新 agent 能无缝继续。

**状态**: 正式

## 适用场景

- 会话 / 上下文即将耗尽，工作要交给新会话
- 用户说"整理一下交接 / 下个会话继续"
- 阶段收尾（发布完成、大任务交付）时固化上下文

## 使用说明

### 产出

一份**交接文档**（存到系统临时目录，**不放工作区**——它是过程工件不是项目文档），使新 agent 能继续工作。

### 内容规则

- **不重复其他工件已捕获的内容**（spec、计划、ADR、issue、commit、diff）——**按路径 / URL 引用**它们即可；
- 包含 **"建议技能"节**：列出新 agent 应加载的技能 ID（如 `diagnosing-bugs`、`code-review`）；
- **脱敏**：API key、密码、个人身份信息一律剔除；
- 用户给了参数时，把参数当作"下个会话焦点"，据此裁剪文档。

### 建议结构

```markdown
# 交接：<主题>
## 状态（已完成 / 进行中 / 未开始，各一两行）
## 关键决策与出处（引用 ADR / commit / 文件路径，不复制内容）
## 下一步（可执行的下一步 + 验证方式）
## 建议技能（skill_id 列表）
## 环境（工作目录、分支、需重启 / 构建的事项）
```

### 与天演压缩机制的关系

- 天演会话有**自动压缩**（ContextPipeline 摘要）；handoff 是**手动、可控、跨会话**的交接件——两者互补；
- 天演压缩的"摘要 + 会话 URI 指引（`vfs_read` 检索原始记录）"与本技能的"不重复内容、只引用路径"原则一致。
