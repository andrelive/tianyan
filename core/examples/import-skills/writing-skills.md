# 写好技能（Writing Skills）

**ID**: `writing-skills`

**版本**: 1.0.0

**描述**: 写 / 改技能的词汇与原则——让技能**可预测**（同一过程每次执行），是天演技能生态（VFS 方法论）的质量参考。

**状态**: 正式

## 适用场景

- 给天演写新技能（VFS `skill/{id}`）、评审既有技能
- 评估自动生成技能（GEPA）的质量
- 技能检索命中率低 / 技能被加载后行为不稳定时

## 使用说明

### 根德：可预测性

技能存在的意义是**从随机系统中榨出确定性**。**可预测**——agent 每次走**同样的过程**（不是同样的输出）——是根本美德；下面所有杠杆都为它服务。

### 触发（两种模式）

- **模型调用式**：保留 description → agent 可自主触发、其他技能可触达；代价是**上下文负载**（description 每轮都在窗口里）。description 面向模型写，塞满触发词（"当用户想…、提到…时使用"）。
- **用户调用式**：不给 agent 看 description——只有人输名字才能触发。零上下文负载，但花**认知负载**（人得记着它存在）。
- 选择：只有"agent 必须自主触达"或"其他技能必须触达"时才做模型调用式。

### 写 description（模型调用式）

description 干两件事：说清技能是什么 + 列出**应触发它的分支**。每个词都增加上下文负载——比正文更狠地剪：

- **把技能的头牌词放最前**（description 是触发发生的地方）；
- **一个分支一个触发**——同义改写同一分支 = 重复，合并；
- **砍掉正文已有的身份介绍**——description 只留触发 + "当其他技能需要…"的触达句。

### 信息层级（渐进披露）

技能由两类内容构成——**步骤**与**参考**：

1. **技能内步骤**——有序动作，主要层级；每步以**完成判据**收尾（agent 能判定"完成没"吗？关键处要"穷尽"——"每个被改的模型都有交代"，不是"产出一份变更清单"；含糊判据招致**过早收工**）；
2. **技能内参考**——按需查阅的定义 / 规则 / 事实（可以是一整片平级规则，不是坏味道）；
3. **外部参考**——推到 `SKILL.md` 以外单独文件，靠**上下文指针**触达、需要时才加载。

**渐进披露** = 把内容沿梯子下放（技能文件夹里链接 .md），保持顶层可读。**分支**是披露测试的试金石：每条分支都要的 → 内联；只有部分分支到的 → 放指针后。

### 何时拆分

- **按触发拆**：出现独立的头牌词、或别的技能必须触达它；
- **按序列拆**：后续步骤会让 agent 想赶当前步骤的工（过早收工）时，把后续步骤拿远点。

### 剪枝

**每个含义保持单一事实来源**——行为改动是一处编辑。

### 本地实例（天演语境）

- 天演技能 = VFS 方法论文档：**L0 abstract**（检索发现）→ **L2 content**（按需加载）——即本技能的"渐进披露"落地；
- 自动生成技能的门槛对照：description 是否有触发分支、正文是否有可检查的完成判据、是否单一事实源。
