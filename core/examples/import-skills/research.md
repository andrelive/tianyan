# 调研（一手来源 + 落盘）

**ID**: `research`

**版本**: 1.0.0

**描述**: 把"查阅与阅读的苦力活"委托给后台子代理，产出带引用、可复核的调研文档。

**状态**: 正式

## 适用场景

- 调研一个主题 / API 事实 / 参考实现（如"参考某个外部系统怎么做 X"）
- 需要"可引用的结论"而不是道听途说
- 阅读量大、适合后台并行时

## 使用说明

### 流程

1. **派后台子代理去做调研**——主线继续干别的、不被阅读阻塞。
2. 子代理职责：
   - 对**一手来源**做调查——官方文档、**源代码**、规范、第一方 API；**不是**二手的转述文章。每条论断**回溯到拥有它的源头**；
   - 把发现写入**单个 Markdown 文件**，**每条论断标注来源**（文件:行号 / URL / 提交号）；
   - 存到仓库既有的同类笔记位置（匹配现有约定；没有约定时放个合理位置并说明）。
3. 主 agent 复核关键论断（抽样验证引用——**引用与原文对不上 = 整份可疑**）。

### 反模式

- 以博客 / 摘要为最终依据（它们可能转述失真）——博客只是**线索**，源头才是依据；
- 结论没有出处（无法复核 = 不算调研）；
- 只给"我认为"式的记忆性断言——讨论数据结构 / API 语义 / 框架行为时须核实规范或源码。

### 本地实例（天演语境）

- "参考 DSH 实现"类任务即本模式：直接读外部源码（一手），逐条引用（文件:行号 + 注释原文），产出对比报告；
- 与天演记忆纪律呼应："结论必须有证据——未验证论断会被否定"。
