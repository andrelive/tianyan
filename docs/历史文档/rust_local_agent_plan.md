# Rust本地智能体开发规划方案

> **配套文档**: 本方案中的代码示例已迁移至 [rust_local_agent_code_examples.md](./rust_local_agent_code_examples.md)，便于独立阅读和维护。

## 1. 项目概述

本项目旨在基于Rust语言开发一个本地智能体系统，核心定位为"大模型驱动的本地执行助手"。系统以大模型为核心智能引擎，采用**统一URI + 分层摘要架构**实现所有上下文的统一管理，包括用户偏好、短期记忆、长期记忆、知识库、技能等。设计遵循最小依赖原则，不使用现有agent框架，仅在必要时集成外部工具。

### 1.1 核心设计理念

- **大模型优先**：充分利用大模型的上下文理解与推理能力，避免重复造轮子
- **统一上下文架构**：采用文件系统范式，所有上下文通过统一URI标识和访问
- **分层摘要机制**：L0/L1/L2三层结构，实现按需加载和Token优化
- **云端模型优先**：支持OpenAI兼容接口的云端模型服务
- **最小依赖原则**：核心功能自研，外部依赖按需引入

### 1.2 架构创新点

本方案借鉴OpenViking的设计理念，创新性地采用**文件系统范式**重构上下文管理：

| 传统方案 | 本方案 |
|---------|--------|
| 多个独立存储（向量库、配置文件、代码） | 统一虚拟文件系统 |
| 扁平向量检索 | 目录递归检索 |
| 黑盒式RAG | 可视化检索轨迹 |
| 机械记录对话 | 自动记忆迭代 |
| 碎片化上下文 | 统一URI标识 |

### 2.2 统一URI设计

所有上下文通过统一的`tianyan://`协议标识：

```
tianyan://<category>/<sub_category>/.../<item>

示例：
tianyan://user/profile/basic_info           # 用户基本信息
tianyan://user/preferences/theme            # 用户主题偏好
tianyan://memory/sessions/2024/01/15/chat   # 特定日期的会话
tianyan://memory/events/project_decision    # 项目决策事件
tianyan://knowledge/documents/api_spec      # API文档
tianyan://knowledge/projects/tianyan/src    # 项目源码
tianyan://agent/skills/file_operations      # 文件操作技能
tianyan://agent/patterns/code_review        # 代码审查模式
```

### 2.3 三层分层摘要机制

每个上下文条目自动生成三层摘要：

```
tianyan://knowledge/documents/api_spec/
├── .abstract.md      # L0层：~100 tokens，用于向量检索和快速过滤
├── .overview.md      # L1层：~2K tokens，用于内容导航和重排序
└── content.md        # L2层：完整内容，按需加载
```

| 层级 | Token限制 | 用途 | 加载时机 |
|------|----------|------|---------|
| L0 Abstract | ~100 | 向量检索、快速过滤 | 首次检索时 |
| L1 Overview | ~2K | 内容导航、重排序 | 定位到目录后 |
| L2 Detail | 无限制 | 完整内容 | 需要详细信息时 |

### 2.4 数据流转示意

```
用户输入 → 意图分析 → 目录递归检索 → 分层加载 → Prompt构建 → 大模型推理 → 技能执行 → 上下文更新
    ↑                                                                              │
    └────────────────────────── 记忆自迭代 ───────────────────────────────────────┘
```

### 3.2 上下文条目结构

> **代码实现详见**: [代码示例文档 - 1.1 内容层级与上下文条目](./rust_local_agent_code_examples.md#11-内容层级与上下文条目)

每个上下文条目包含以下核心组件：

- **uri**: 唯一标识符 (tianyan://...)
- **is_directory**: 是否为目录
- **三层摘要**: abstract_content (L0)、overview_content (L1)、detail_content (L2)
- **metadata**: 元数据（分类、标签、来源、内容类型）
- **向量表示**: abstract_embedding、overview_embedding（内存中临时存储）
- **访问统计**: 创建时间、更新时间、访问次数、重要性评分

### 3.3 目录递归检索策略

**核心原则**：所有向量检索统一通过Qdrant进行，文件系统只负责内容存储。

```
┌─────────────────────────────────────────────────────────────────┐
│  Step 1: 意图分析                                               │
│  - 分析用户查询                                                 │
│  - 生成查询向量                                                 │
│  - 确定目标范围（可选）                                         │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 2: L0向量检索（通过Qdrant）                               │
│  - 在abstract向量空间中检索候选（返回3倍Top-K用于后续重排序）    │
│  - 快速定位高相关性条目                                         │
│  - 返回候选URI列表                                              │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 3: L1向量检索（通过Qdrant）                               │
│  - 在overview向量空间中对候选进行重排序                         │
│  - 更精确的语义匹配                                             │
│  - 返回最终结果列表                                             │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 4: 内容加载                                               │
│  - 根据URI从文件系统加载对应层级内容                            │
│  - 高相关性：加载L2完整内容                                     │
│  - 中相关性：加载L1概览                                         │
│  - 低相关性：仅返回L0摘要                                       │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 5: 结果聚合                                               │
│  - 按相关性排序结果                                             │
│  - 根据Token预算选择加载层级                                    │
│  - 记录检索轨迹                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**注意**：目录递归检索的"递归"体现在Qdrant的层级结构匹配上，而非文件系统遍历。

> **流程说明**：以上展示完整的5步检索流程。代码实现详见 [代码示例文档 - 2.4 双层检索协调器](./rust_local_agent_code_examples.md#24-双层检索协调器)。

> **index.json 与 Qdrant Payload 的用途区分**：
> - **index.json**：用于文件系统层面的目录快速浏览，包含条目名称和摘要文本，方便用户直观查看目录内容
> - **Qdrant Payload**：用于向量检索，包含URI、分类等元数据，支持按类别过滤和语义检索

### 4.3 知识库管理模块

#### 4.3.1 知识摄入与分类

**设计理念**：所有知识（用户上传或智能体生成）统一按类型分类存储，由大模型自动判断知识类型并进行分类。知识来源通过元数据字段标识，不影响存储结构。

**支持的文件类型**：

| 类型 | 格式 | 处理方式 |
|------|------|---------|
| 文档 | PDF、DOCX、TXT、MD | 文本提取 → 摘要 → 向量化（超长文档额外智能分片） |
| 代码 | RS、PY、JS、TS等 | AST解析 → 结构化 → 摘要 → 向量化 |
| 数据 | CSV、JSON、XML | 结构解析 → 模式提取 → 向量化 |
| 表格 | XLSX、XLS | 内容提取 → 表格理解 → 向量化 |
| 图片 | PNG、JPEG、GIF | VLM理解 → OCR → 描述生成 → 向量化 |

**处理流程**：
```
知识输入 → 格式识别 → 内容提取 → 类型分类（大模型） → 摘要生成 → 向量化 → 统一存储
                ↓                              ↓
         元数据提取（文件名、大小、类型、来源）  分类决策（documents/images/code/data/projects）
         
注意：普通文档无需分片，仅超长文档（如书籍）采用智能结构化分片
```

**关于长文档的处理策略**：

对于超长文档（如书籍、大型技术文档），采用**智能结构化分片**而非机械切分：

```
长文档处理流程：
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  结构分析（由大模型完成）：                                    │
│  1. 识别文档结构（章节、段落、语义边界）                       │
│  2. 提取目录/大纲                                            │
│  3. 确定分片边界                                             │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  智能分片存储（每个分片独立URI）：                              │
│                                                              │
│  tianyan://knowledge/documents/book_001/            │
│  ├── .abstract.md           # 整书摘要                       │
│  ├── .overview.md           # 整书概览 + 目录                │
│  ├── toc.json               # 目录结构                       │
│  ├── chapters/              # 按章节分片                     │
│  │   ├── chapter_01/                                        │
│  │   │   ├── .abstract.md   # 章节摘要                      │
│  │   │   ├── .overview.md   # 章节概览                      │
│  │   │   └── content.md     # 章节内容                      │
│  │   ├── chapter_02/                                        │
│  │   └── ...                                                │
│  └── full_content.md        # 完整内容（可选，大文件可省略）  │
└─────────────────────────────────────────────────────────────┘
```

**分片原则**：
- **语义完整性**：按章节、段落、主题边界分片，保持语义完整
- **独立可检索**：每个分片有独立的URI和分层摘要
- **层级关联**：父级摘要聚合子级内容
- **按需加载**：检索时先匹配章节摘要，再按需加载具体内容

#### 4.3.2 图片知识处理

**处理策略**：

| 场景 | 处理方式 | 存储内容 |
|------|---------|---------|
| 截图/界面 | OCR + VLM理解 | 文本 + 描述 + 向量 |
| 照片/图像 | VLM描述生成 | 描述 + 标签 + 向量 |

```
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  统一文本构建：                                               │
│  将VLM描述 + OCR文本 + 元素标签 合并为统一文本表示            │
│                                                              │
│  示例：                                                       │
│  "这是一张系统架构图。图中包含Web层、API层、数据库层三个      │

│  L1: 详细描述 + 关键元素列表（~2K tokens）                   │

└─────────────────────────────────────────────────────────────┘

    ▼
┌─────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────┘
```

#### 4.3.3 多模态检索策略

**统一检索架构**：

```
用户查询（文本/图片）
    │
    ▼
┌─────────────────────────────────────────────────────────────┐

│     - 文档通过文本内容向量匹配                                │
│     - 图片通过统一文本向量匹配                                │
│  3. 返回混合结果                                              │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  图片查询：                                                   │
│  1. 图片视觉向量化                                            │
│  2. 通过Qdrant检索visual向量空间                              │
│  3. 返回相似图片                                              │

```

**设计原则**：
- **统一文本表示**：图片的VLM描述+OCR文本+标签合并为统一文本，与文档使用相同的检索机制
- **视觉向量支持**：所有图片生成视觉向量，支持以图搜图功能
- **简化检索逻辑**：文本查询无需区分内容类型，统一处理

```
                              ▲
                              │ ContentLoader trait
                              │
```

**设计优势**：
1. **简化检索逻辑**：文本查询统一处理，无需区分文档和图片
2. **以图搜图支持**：所有图片生成视觉向量，支持图片相似性检索

## 9. 性能优化策略

### 9.1 分层加载优化

- **L0优先**：优先加载和检索L0摘要，快速过滤无关内容
- **按需深入**：仅在必要时加载L1/L2内容
- **缓存策略**：缓存高频访问的摘要内容
- **预加载**：预测性预加载可能需要的上下文

### 9.2 检索优化

- **向量索引**：建立高效的向量索引结构
- **并行检索**：并行执行多个目录的检索
- **增量更新**：支持增量更新摘要和向量
- **查询优化**：优化查询向量生成

### 9.3 存储优化

- **分层存储**：热数据内存、温数据SSD、冷数据磁盘
- **压缩存储**：对向量数据进行压缩
- **异步持久化**：后台异步写入存储
- **定期清理**：清理过期和低价值内容

### 9.4 资源管理优化

- **内存池**：预分配内存减少碎片
- **并发控制**：合理的并发度设置
- **资源监控**：实时监控资源使用
- **优雅降级**：资源紧张时降低服务质量

## 10. 潜在挑战及应对方案

### 10.1 挑战一：摘要质量

**挑战**：自动生成的摘要可能丢失关键信息

**应对方案**：
- 多轮摘要验证
- 关键信息提取保护
- 用户反馈优化
- 人工审核机制（可选）

### 10.2 挑战二：检索精度

**挑战**：递归检索可能遗漏或引入无关内容

**应对方案**：
- 多维度相关性评分
- 检索轨迹可视化调试
- 用户反馈学习
- A/B测试优化参数

### 10.3 挑战三：存储效率

**挑战**：三层摘要会增加存储开销

**应对方案**：
