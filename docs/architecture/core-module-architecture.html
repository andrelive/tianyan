01全景图：core 在系统架构中的位置与内部 4 层分层

左：Tauri → Server → Core → 存储 的完整调用链；右：core 内部 15 模块按 4 层组织（L1 基础 / L2 基础设施 / L3 能力 / L4 编排）。

⚠️ 定时任务注册点在 server/src/lib.rs（非 core）：TaskScheduler 由 server 层装配，且仅当 has_providers()（存在可用模型）时注册。snapshot 是唯一的 VFS 例外（ADR-006，独立文件存储于 {data_dir}/snapshots/）。
启动装配链（server 层，供全景参考）：Tauri → server::start_server → bootstrap_app_vfs（SqliteBackend + LanceDbVectorStore + ModelServices + VFS Builder）→ AppState（SummaryService + SkillRegistry + AgentBuilderFactory）→ AgentBuilder：AgentLoop + ToolRegistry(10 工具) + ApprovalWorkflow + VerificationGate + ContextPipeline + DualLayerRetriever + SnapshotManager + SkillLearningEngine → TaskScheduler 注册 4 任务 → axum serve。

3 处反向边 / 环（C3 节）：① context ↔ observability 环（context→observability 为 UsageStats 埋点；observability→context 为 RetrievalTrace 类型依赖）；② vfs → observability（SqliteBackend 复用 observability::SqliteDb 连接，backend/sqlite.rs:13）；③ common → config（init_logging 取 LoggingConfig，logging.rs:10）。

03VFS 统一存储模型（ADR-001）：三层内容 · 写入双入口 · RRF 检索链路

所有上下文类型统一写入 VFS → SummaryEngine 生成 L0/L1 → LanceDB 向量化；查询 → embed → RRF 融合检索 → 分层加载。向量化仅 2 个入口。

E1 · 三层内容与配额

命名空间统一 tianyan://：memory/ · knowledge/ · agent/learned/ · skill/ · session/ 等。
write() 只写单层，不自动摘要 / 向量化——向量化由 2 个入口显式触发。

E2 · 写入链路（向量化仅 2 入口）

便捷方法：write_content(L2) / write_abstract(L0) / write_overview(L1)。

E3 · 检索链路（DualLayerRetriever::retrieve）

⑥ 检索轨迹：RetrievalTrace → UsageStats.record_retrieval_trace（FIFO 500 条）。图像双通道（E4 节）：VLM 文本描述（L0/L1）+ embed_image → visual_vector（visual_vector 存储于向量库，VFS 便捷检索入口已移除（零调用））。

04对话处理时序图：Agent::process_message 全链路（泳道）

泳道：Server（外部入口）→ Agent（协调）→ AgentLoop / ContextAssembler → Session → VFS。编号对应 F 节 9 个阶段（含压缩与后台 GEPA）。

消息流（ADR-002 / J 节）：LLM 响应 → message_to_structured → SessionManager（VFS JSONL）；组装时 structured_to_messages → LLM 传输格式（User / Assistant / Tool / System）；compression_marker 标记压缩锚点（前缀匹配：soul → rules+memories → history → input）。

05AgentLoop 迭代循环：3 分支 + 审批降级链路（F2 / F3 节）

LLM → 工具 → LLM 循环；3 种退出分支：Answer 结束 / ask_user 中断 / 待审批追问。下方为审批决策序与风险分级表。

工具门控（F2 节）：call_skill → skills::SkillExecutor 桥接；write_file / execute_command → SecurityPolicy + ApprovalWorkflow；verify_build → VerificationGate（LlmJudge）；工具失败 → RuleRecorder 即时记录（agent/learned/）；每次执行 → GEPA ExecutionHistory（供 learn_from_history）。

F3 · 审批决策序与风险分级

决策序：auto_approval 规则 → Safe 直接批准 → Critical 默认拒绝 → unattended 自动批（审计）→ is_action_confirmed（确认指纹）→ wait_for_human_approval（pending 队列 + oneshot 等 GUI，超时默认拒绝）。

06检索流程详图：DualLayerRetriever 8 步（RRF 融合 + ContentLoadStrategy 阈值）

查询 → 意图分析（无 embedding）→ 双列独立 ANN → RRF 融合（k=60）→ memory 偏置 ×1.15 → 新鲜度融合 → 分级加载 → 轨迹记录。

分级含义（E1 节）：L0 Abstract（≈100 tok，abstract_vector）用于向量搜索与快速过滤；L1 Overview（≈2K tok，overview_vector）用于内容导航与重排序；L2 Detail（∞，无向量列）为完整内容、命中后按需加载。检索轨迹（RetrievalTrace）作为"黑匣子"存入 observability，FIFO 500 条。

07知识摄入流程：KnowledgeIngestor::ingest（文档 / 图像双通道）

调用方：knowledge_ingest 工具（LLM 自主触发）+ server /api/v1/knowledge/ingest。去重 → 分类型 → 摘要 → 三层全写 → 向量索引。

图像双通道（E4 节）：VLM 生成文本描述 → 文本 embedding（L0/L1）+ embed_image → visual_vector（视觉相似度搜索 visual_vector 存储于向量库，VFS 便捷检索入口已移除（零调用））。两通道汇合后走相同的摘要 → 三层全写 → index_entry 链路。

08定时任务图：4 个任务时间线（注册点在 server，非 core）

summary_generation（5min）· memory_extraction（10min）· rule_extraction（15min）· garbage_collection（6h）。SummaryTask 是向量化兜底入口。RuleRecorder / RuleSuggester 不是独立定时任务。

调度机制（H 节）：TaskScheduler::start_with_scheduler → parse_cron_interval → 每任务 tokio::spawn + interval 循环。仅 has_providers()（存在可用模型）时注册。
⚠️ rule_recorder / rule_suggester 不是独立定时任务：RuleRecorder 由工具失败即时触发（非定时）；RuleSuggester 是 RuleTask 的内部组件。

09GEPA 技能进化闭环 + 记忆提取 + 工具失败规则记录

闭环：每次工具执行 → 记录 → learn_from_history → 生成技能 → 存储 → 评估 → call_skill 复用 → 再次执行。旁路：工具失败 → 规则；会话 → 记忆。

门控与阈值（I 节）：enable_auto_learning && history.len() ≥ 3；过滤 success ≥ 2；分组每组 ≥ 2 条成功执行；评估阈值 0.5（Deprecate）/ 0.8（Improve）。技能与记忆的向量均由 SummaryTask 兜底补齐（见③⑧）。
