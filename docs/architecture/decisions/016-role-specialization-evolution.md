# ADR-016: 角色化子智能体的自演化分工

**日期**: 2026-08-15
**状态**: 提议（待评审）
**影响范围**: 角色注册表（`core/src/agent/roles.rs`）、技能学习引擎（`core/src/skills/learning/`）、
委托工具（`core/src/agent/tool_registry/agent_ops.rs`）、上下文组装（`core/src/context/assembler.rs`）、
会话存储（`core/src/session/`）、命令执行（`core/src/executor/command.rs`，已落地）

---

## 背景

1. **注意力分散与 token 消耗**：主 agent 的系统提示、工具清单、技能集合随使用持续膨胀，
   单上下文承载全部能力导致注意力稀释与请求体量增长。人类组织的解法是社会分工——
   专业角色各持有限工具与聚焦提示，本 ADR 将同一机制引入天演。
2. **现状一：角色委托已存在但是静态的**。`delegate_to_agent` + `AgentRole`
   （model / system_prompt / 工具白名单 / max_turns / timeout）已提供子智能体执行机制，
   但角色只有两个来源：内置写死（researcher / editor / reviewer）与 `[agent_roles]` 用户手写。
   用户手写无数据支撑，效果不确定且可能拖累整体；内置角色无法随使用演化。
3. **现状二：技能进化管线已存在但产物是技能不是角色**。GEPA 引擎从执行轨迹
   （`ExecutionHistory`）学习技能（分类 → 生成 → G2b 验证门 → dedup 门 → VFS 落盘 →
   会话边界刷新），但角色与技能是两个世界：技能无系统提示与工具白名单，角色无进化管线。
4. **业界印证**：oh-my-openagent Team Mode 将 subagent 与 skill 统一进同一 resolver；
   DeepSeek Harness 提供 durable subagent（持久会话 + `send_message` 续聊）与
   fire-and-forget 后台任务语义（非阻塞观测 + 显式 kill + 完成通知）。
5. **运行教训**：oh-my-openagent 的 bash 工具同步等待进程退出，启动常驻服务（dev server）时
   卡死（opencode #22012 / #20902 / #30816）；DeepSeek Harness 以任务生命周期与工具调用
   解耦规避。天演已在执行层落地该机制（见决策 7）。

## 决策

### 1. 统一角色实体模型：角色是可进化的实体，不是配置

- `AgentRole` 扩展元数据：`source: Builtin | User | Learned`、`version: u32`、
  `status: Active | Experimental`、`lineage: Option<String>`（进化自谁，回退链）。
- `RoleRegistry` 从「内置 HashMap + 配置覆盖 + 学习追加」的三段拼接，收敛为**单一注册表**：
  所有角色同构、同一引用方式（`delegate_to_agent` 按名解析），来源只是元数据，无来源歧视。
- 角色生命周期：出生（内置种子 / 用户种子 / 学习生成）→ 进化（GEPA 更新）→ 退役（被取代或手动移除）。

### 2. 自演化优先：用户手写降级为种子来源

- 用户手写角色（`[agent_roles]`）**保留兼容但不再是推荐路径**：UI/文档不再引导手写，
  定位为「初始种子」——学习引擎可基于真实数据修正它（手写提示词/白名单的缺陷
  由成功率数据暴露并修正），用户配置不豁免演化。
- **注册表持久化到 VFS**（`agent_role/` 命名空间）：演化产物脱离代码与配置文件存活；
  内置角色 = 首次启动写入的种子，之后统一由演化实体接管。用户配置仅作为种子来源之一，
  启动时 upsert（仅当注册表中不存在或用户配置显式变更）。
- **防劣质进化闸门**（否则「学习可改一切」不成立）：
  a. G2b 候选验证门（LLM 打分 0-10，<6 标记试验性，不落地为正式）；
  b. **成功率门控**：改进版在真实委托中成功率 ≥ 旧版才升级（复用 GEPA_IMPROVE 回写机制），
     否则保留旧版并记录改进失败；
  c. **版本历史**：`lineage` 链支持回退到上一版或还原出厂种子。

### 3. 双管线共生：技能进化原样保留，角色学习并行

- 技能学习管线（`ExecutionHistory` → 技能）**零改动保留**——技能是必须的，角色不能替代技能。
- 角色学习管线与技能管线**共享采集、分开生成**：同一份执行轨迹，技能引擎产出技能，
  角色引擎产出 `AgentRole`（任务类型聚类 + 重复长工具序列分析）。
- **编排技能**：角色生成/更新时**同步产出（或更新）一个编排技能**（落 `skill/learned/`）：
  内容 = 该角色的触发条件、建议工作流（如 researcher → editor → reviewer 组合）、
  注意事项与反模式。主智能体经既有技能渐进披露发现编排技能，从而知道「何时委托、怎么组合」。
  角色与编排技能一对一耦合，角色进化时同次生成调用内更新。

### 4. 渐进披露：delegate 描述 = 角色 L0 摘要

- `delegate_to_agent` 工具描述展示**角色 L0 摘要列表**（名字 + 一句话职责 + 工具数 + 激活状态），
  每行极短；完整系统提示与工具白名单仅委托发生时加载（与技能 L0→L2 同一哲学）。
- **试验性角色只展示、不可调用**（主 agent 可据此评估候选，正式角色才可被引用）。
- 角色摘要段是**动态前缀段**（见决策 6），不进静态工具定义。

### 5. durable 角色会话：三态委托，主智能体自主决策

- `delegate_to_agent` 增加会话语义：`session: "continue" | "new" | "discard"`——
  **决策权在主 agent**（系统只提供机制与决策依据，不强制）。
  - `continue`：续用该角色的持久会话（同类连续任务、长链条工作——领域记忆复用，前缀缓存可命中）；
  - `new`：开新会话（新领域、状态可疑、需要干净上下文时）；
  - `discard`：显式废弃旧会话（释放其记忆的过期事实，防状态污染）。
- 角色会话以 JSONL 持久化于 VFS（复用会话存储，带 role 标记）；委托时携带会话年龄/任务数
  （主 agent 决策依据）；无引用归档 + 并发/总量上限（防失控纪律与委托深度/并发上限一致）。
- 通信仍走委托工具 + 消息注入（ADR-013），**不引入事件总线**（见 REJECTED #17）。

### 6. 前缀缓存分块：static/dynamic split + 会话内锁定

- 主 agent 请求前缀按稳定性降序分块（业界共识：Anthropic prompt caching 静态前缀 +
  static/dynamic split）：
  `1. 根提示词（soul + rules）→ 2. 工具定义 → 3. 角色 L0 摘要段 → 4. 技能 L0 摘要段 → 5. history`
- **会话内锁定**（扩展 ADR-012 快照体系）：角色摘要段与技能摘要段纳入 `SessionHeader` 快照，
  会话内不刷新（前缀字节稳定 → 缓存命中 + 语义一致）；刷新点 = 启动全量 / 新会话增量 / 压缩点
  （三个免费刷新点，与 ADR-012 完全同构）。
- **增量通知**：压缩点/会话边界后若角色或技能有增量，注入轻量 System 通知（「新增角色 X：一句话」），
  前缀本体不动，缓存不失效。
- 推论：角色集合必须控速（dedup 门 + 退役机制），否则摘要段自身膨胀且频繁变化，
  反而破坏第 2 段（工具定义）的缓存——与「防专家动物园」是同一约束的两面。

### 7. 后台命令原语（已落地，本 ADR 引用）

执行层已完成对标 DSH 的后台任务机制（提交 `6b5cc083`、`9693b73c`）：
- `execute_command(background=true)` fire-and-forget：立即返回 task_id/pid/log_file；
- `command_status` / `command_list` / `command_kill`：非阻塞观测 / 列表 / 杀进程树；
- 超时与终止**杀进程树**（Windows taskkill /T /F；Unix 进程组 kill），消灭孤儿服务进程；
- 完成通知：终态注入父会话 System 消息（含 remaining join 信号），唤醒语义 = `allComplete || failure`
  （ADR-013，REJECTED #18）。
角色委托场景（子智能体启动/管理服务）由此获得与主 agent 相同的非阻塞执行能力。

## 后果

### 正面
- 主 agent 上下文瘦身：系统提示与工具清单按角色裁剪，注意力集中 + token 消耗下降；
- 分工随使用涌现：角色是数据长出来的（真实轨迹 + 成功率），非手写拍脑袋；
- 内置角色可进化：出厂种子随使用演化，无需等版本发布；
- 领域记忆复用：durable 会话让同类任务不再白纸起跑。

### 负面 / 代价
- 注册表膨胀风险：角色集合需 dedup/退役/激活阈值三重控速（否则摘要段伤缓存 + 路由选择退化）；
- 学习质量依赖数据：样本少时生成的角色可能劣质——G2b 门与试验性分级兜底，仍可能产出噪音候选；
- 自动更新用户角色可能违背用户直觉：靠版本回退 + 成功率门控缓解；
- durable 会话状态污染：过期事实残留——三态委托的 discard 是显式出口，主 agent 判断失误时
  仍可能用错状态（决策权在主 agent 的固有代价）；
- 注册表 VFS 写入量：角色演化低频（学习阈值门槛），可接受。

## 边界条件（违反即重新评估）

- 角色集合在控速机制生效后仍持续膨胀（> 数十个）且路由错误率上升——重新评估自动路由必要性；
- 学习演化导致内置角色可用性显著下降（回退机制未能兜底）——重新评估「学习可改内置」；
- durable 会话状态污染造成实际任务失败且 discard 语义未缓解——重新评估会话生命周期强制策略；
- 本设计出现平级多 agent 协作形态（Agent Teams）——触发 REJECTED #1/#17 的重新评估条件，
  届时规划状态/事件机制可能作为共享实体回归，与本 ADR 叠加而非替代。

## 与既有否决项的关系

| 否决项 | 关系 |
|--------|------|
| #1 独立 Planner | 不冲突：本设计是角色化委托的演化（主从），不产生独立规划组件 |
| #14 ACP 控制中心 | 不冲突：仍是内部子任务编排，不驱动异构外部 agent |
| #17 全事件驱动 | 不冲突：durable 会话通信仍走委托工具 + 消息注入 |
| #18 每任务唤醒 | 一致：唤醒语义沿用 allComplete || failure |
| 后置：大任务自动分解 | 正交：角色分化不自动分解任务，分解仍由模型自行决策 |

## 后续演进（占位，非本 ADR 决策）

- **P2 机会检测**：未委托但重复出现的长工具序列 → 提炼「该分出去」的角色候选（需更长观察窗口）；
- **P3 路由优化**：LanceDB 向量匹配任务描述 vs 角色摘要；激活/退役阈值调优；
- **P3 会话升级**：角色会话压缩、并发委托锁、多角色协作会话图。
