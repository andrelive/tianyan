# ADR-022: 会话绑定的任务面板与任务语义分层

- 状态：已采纳（Accepted）
- 日期：2026-08-30
- 关联：ADR-003（组件工具化）、ADR-013（统一消息通知与唤醒）、ADR-020（数据库门面）

## 背景

0.2.0 验证暴露三处交互问题：

1. **「计划」全局栏目语义错位**：待办/目标是辅助 LLM 推理的临时工具产物
   （对齐 DSH 的 `todo_write`/`goal`：composer 上方停靠面板、空即消失），
   不是全局持久展示的用户计划页。全局展示会引入跨会话噪音（上个会话的
   已完成计划永久可见），且完成后的条目毫无展示价值。
2. **「任务」栏目混装三种异质内容**：内置调度任务（系统 cron，洞察已展示）、
   定时任务（openclaw 式周期 AI 工作）、后台任务（会话发起的委托/终端任务）
   三者受众与生命周期完全不同，硬塞进三个 tab 是错误聚合。
3. **数据目录搬迁交互**：数据目录可直接编辑（应只读）；搬迁入口不突出；
   目标目录为空的前置校验只藏在确认文案里。

## 决策

### 1. todo/goal 会话绑定 + 临时展示

- `TodoItem`/`Goal` 增加 `session_id`（`#[serde(default)]` 兼容旧数据；
  旧数据 `None` 不进任何会话面板）。
- `DynamicToolExecutor::execute` 增加 `session_id` 参数（随调用链显式传递，
  与内置工具约定一致）——`todo`/`goal` 工具创建时归属当前会话，
  list/update/delete 只作用于本会话条目（跨会话 id 一律 not_found）。
- 展示收敛到会话页输入框上方停靠面板（`SessionTodoPanel`）：只显示活跃
  条目（非 completed），全部完成即整面板消失；无独立路由、无全局栏目。
- 删除会话级联清理其 todo/goal（`delete_by_session`）。
- REST `GET /todos`/`GET /goals` 支持 `?session_id=` 过滤（面板数据源）；
  create 接受可选 `session_id`（正常路径由工具归属，直传便于 QA）。

### 2. 任务语义分层（移除「任务」栏目）

| 任务类型 | 语义 | 归属展示 |
|---------|------|---------|
| 内置任务 | 系统 cron（摘要/GC/演化等） | 「洞察」栏目（已有） |
| 定时任务 | 到点调用智能体的周期 AI 工作 | 独立一级栏目「定时任务」（`/scheduled`） |
| 后台任务 | 会话发起的委托/终端任务 | 会话页停靠条（`SessionTasksPanel`；**已被 ADR-026 替代为右侧任务面板** `AgentTasksPanel`） |

- 后台任务只展示 pending/running（可取消）；完成即隐——结果经 ADR-013
  唤醒轮由主 agent 汇总进会话流，不重复展示终态卡片。
- 侧边栏运行中后台任务角标移至「会话」图标（任务按会话归属后全局
  「任务」角标失去语义）。

### 3. 数据目录搬迁交互

- 「数据目录」改为只读展示（唯一修改途径 = 搬迁，杜绝绕过校验的直改）。
- 「数据搬迁」按钮 → 模态对话框：原生目录选择器（tauri-plugin-dialog，
  浏览器/E2E 环境回退手动输入）→ 确认。
- 空目录校验单点在后端 `validate_migration_target`（非空 → 400 就地报错，
  **不触发关停**，可重试）；校验通过才写迁移请求并优雅关停。

## 后果

- 正面：会话页成为任务信息的唯一会话内出口（对齐 DSH/opencode 的
  session-first 交互）；导航项 -2（任务/计划），语义零损失；搬迁流程
  前置校验可视化。
- 代价：`DynamicToolExecutor` 签名变更（5 个实现 + 测试桩同步）；
  旧 todos.json/goals.json 无会话归属条目静默不可见（一次性迁移成本，
  数据量小）。
- 否决方案：全局计划页保留但加会话过滤（引入双入口漂移，弃）；
  后台任务保留全局 tab（违背会话强绑定，弃）。

## 修订（2026-08-31）：todo 工具批量语义 + 完成条目保留展示

实测反馈四问题：逐条创建/推进调用次数过多；批量中发现新工作或拆子任务
不便；完成条目直接消失无法回看；面板宽度与输入框不一致。

- **批量操作**（对齐 DSH todo_write 的一次性整单写入）：todo 工具
  create 接受 todos 数组一次写整份清单，update 接受 updates 数组
  一次合并多条状态变更，delete 接受 ids 数组；单条形态保留兼容。
  存储层对应 create_many/update_many/delete_many（单次落盘，
  update 原子——任一 id 不存在整体不上盘）。
- **子待办**：TodoItem.parent_id（serde default 兼容旧数据），工具创建/
  更新时校验父待办存在且属于本会话；面板缩进展示。
- **完成条目保留展示**：面板不再过滤 completed——完成项划线 + 对勾
  图标保留在列表中（回看做了什么），无任何条目后面板才消失。替换
  本 ADR 原先「只显示活跃条目，全部完成即消失」的表述。
- **修复存储懒加载竞态**：ensure_loaded 读盘移入写锁内双重检查——
  此前 create/update/delete 不触发加载，新进程首个 create 会把磁盘上
  其他条目全部覆盖（「todo 不存在或不属于当前会话」误报的根因）。

## 修订（2026-10-05）：当前批语义（同源待办单批存在）

实测反馈：todo 永远追加、完成批不消失，面板无限膨胀；且「完成条目
保留展示」的修订把回看能力变成了永久堆积，违背 todo 作为「当前工作
清单」的临时定位。

- **create 自动换批**：本会话已有待办且全部完成时，再 create 先移除
  旧批（删除，非归档）再建立新批；仍有未完成项时新工作**追加**进
  当前批（保留「随时追加」语义，防误删）。
- **新增 close 操作**：清空当前会话全部待办——用户目标变更、现有待办
  不再反映当前意图时智能体主动调用（即使有未完成项）；面板随之消失。
- **完成项划线保留 + 智能体自主清理**：完成项默认划线展示（回看），
  删不删由智能体自行决定（delete 或 close），goal 不联动、不自动归档。
- 同一会话同一时期只存在一批同源待办；旧批数据直接删除（不引入
  archived 状态/归档机制——todo 是临时列表，历史可追溯性由会话消息承担）。
- 前端无改动：删除后轮询自然反映；面板空则整体消失（既有逻辑）。
