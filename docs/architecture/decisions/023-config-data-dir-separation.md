# ADR-023: 配置目录与数据目录分离

- 状态：已采纳（Accepted）
- 日期：2026-08-30
- 关联：ADR-022（会话绑定的任务面板——其中数据目录搬迁交互的延续）

## 背景

0.2.2 用户实测数据搬迁暴露系统性缺陷：配置文件 `tianyan.toml` 位于
`~/.tianyan/`（搜索命中），而 `storage.data_dir` 也指向 `~/.tianyan/`——
配置与数据混居。旧搬迁流程（复制 → 尽力删除源 → 更新配置）在此形态下：

1. 把 `tianyan.toml` 当数据复制到新目录，随后**删除了源配置文件**；
2. `update_config_data_dir` 按固定路径搜索配置 → 已被自己删除 → 报错；
3. 回滚分支把新目录内容复制回旧目录 → **两份全量数据并存**、配置未变；
4. 前端轮询 `/health` 见服务恢复即报「搬迁完成」——回滚被当成功。

## 决策

### 1. 配置目录与数据目录彻底分离

- **配置文件位置写死**：`~/.tianyan/tianyan.toml`（Windows/Linux 同形）。
  不再多路径搜索（`./`、`%APPDATA%` 候选移除）；环境变量
  `TIANYAN_CONFIG` 保留为最高优先级覆盖（e2e/CI 隔离用）。
- **数据目录**：从配置 `storage.data_dir` 读取；默认值
  `%LOCALAPPDATA%/tianyan`（`dirs::data_local_dir`，`TIANYAN_DATA_DIR`
  可覆盖）。与配置目录天然不同位。
- 配置文件**永不搬迁**：搬迁排除清单恒定包含数据目录根部的
  `tianyan.toml` 与迁移请求文件自身。

### 2. 搬迁 = 真"搬"

顺序与失败语义（每步失败模式独立可控）：

1. **复制**（纯新增操作，源目录不动）：排除清单条目跳过；
2. **校验**：源/目标逐文件比对（相对路径集合 + 字节大小），不一致即失败
   并清理不完整副本；
3. **更新配置** `storage.data_dir`：失败 → 清理副本 + 清除请求文件 +
   报错（源目录未动，状态一致）；
4. **强制删除源数据条目**：进入本步**不再回滚**（新目录数据已校验完整、
   配置已指向新目录）；个别文件被占用 → 留作无害残留并在结果
   （`MigrationOutcome.leftovers`）与日志中报告，调用方可稍后手动删除。

排除清单恒定生效，配置文件在整个流程中不存在丢失窗口。

### 3. 失败对用户可见

前端在服务重启后（`/health` OK）**比对重启后 `GET /config` 的
`data_dir` 与用户所选新目录**：不一致说明搬迁已回滚，明确报
「搬迁未生效（已自动回滚）」并保留对话框供重试——不再以服务恢复与否
推断搬迁成败。

## 后果

- 正面：搬迁后旧数据目录仅剩配置文件（混居形态）/ 完全清空（常规形态）；
  任何失败模式下配置文件零风险、数据不双份；失败原因直达用户。
- 代价：多路径配置搜索移除——曾把配置放在 `./` 或 `%APPDATA%` 的
  非标准位置将不再被读取（当前用户明确表示无需兼容）。
- 新目录非空校验维持：若上次搬迁失败残留了副本（0.2.2 遗留），
  需手动清空目标目录后重试。
