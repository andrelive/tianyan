# 已否决决策清单（REJECTED）

> 目的：固化所有**明确不做**的方向及其原因。避免被否决的方向反复进入讨论；
> 若现实情况发生变化（触发条件满足），据此重新评估——届时对照"原否决原因是否仍成立"。
>
> 约定：本文件记录**否决项**（含已删除组件），不占用 ADR 编号（ADR 仅记录已采纳决策）。
> 后置项（延后但未否决）单独列于文末，不属于本清单。

## 1. 独立 Planner 组件（已删除）

- **决策**：不重建。天演历史上存在 `planner/`，已删除。
- **原因**：主 agent 拥有全部上下文（对话历史 + 检索 + 记忆），自身即最好的 planner；独立规划组件 = 上下文搬运 + 规划/执行两段割裂。项目原则"工具不做自主多轮决策，决策权在 LLM"。
- **重新评估触发条件**：出现多 agent 平级协作（Agent Teams 形态）且规划需要跨实例共享时——届时规划状态可能作为共享实体回归，而非组件。

## 2. ModelRouter（已删除）

- **决策**：不做模型自动路由。
- **原因**：路由收益依赖多模型质量差 + 场景可分性，本地单用户场景成本高于收益；用户手动切换（`/config/models/switch`）已满足需求。
- **重新评估触发条件**：引入本地小模型 + 云大模型混合工作流且任务可分派（"日常用小模型、难题用大模型"成为硬需求）时。

## 3. TokenBudget（已删除）

- **决策**：不重建独立 Token 预算组件。
- **原因**：上下文控制已由会话压缩（自动阈值 + 手动）+ 双层摘要（L0/L1）+ 前缀快照承担，预算概念分散在这些机制中。
- **重新评估触发条件**：出现按会话/任务硬性 token 配额的产品需求（如企业计量）时。

## 4. Chunker（已删除）

- **决策**：不对内容做 chunk 分块。
- **原因**：VFS 双层摘要（L0/L1）自然替代 chunk-based RAG（ADR-001）——完整内容写 L2，摘要进向量索引，检索质量与存储效率均优于固定分块。
- **重新评估触发条件**：双层摘要的检索质量在特定内容类型（超长代码库/表格）上出现实测瓶颈时。

## 5. AgentHarness / AgentSkills wrapper（已删除）

- **决策**：不保留 wrapper 层。
- **原因**：功能已由 `Agent` / `ToolRegistry` 直接持有，wrapper 只是转发层，增加间接性。
- **重新评估触发条件**：无（结构性简化，回归即倒退）。

## 6. 插件市场

- **决策**：不做插件市场/技能市场。
- **原因**：天演本地单用户、不公开分发；内部技能系统（`call_skill` + GEPA 进化）已承担扩展性；维护市场 = 生态运营成本。
- **重新评估触发条件**：项目转为公开分发/多用户产品时。

## 7. 用户反馈采集

- **决策**：不做主动反馈采集功能。
- **原因**：现有记忆的 GEPA 进化逻辑（工具失败自动学习规则）已隐式承担"从使用中改进"，显式采集（评分弹窗等）打扰单用户工作流且收益重叠。
- **重新评估触发条件**：需要系统化改进信号（如跨用户聚合、评测数据集建设）时。

## 8. 语音 I/O

- **决策**：不做语音输入输出（STT/TTS）。
- **原因**：本地单用户优先级低；STT/TTS 全链路（唤醒词 + 流式识别 + 合成）复杂度高且与核心 agent 能力正交。
- **重新评估触发条件**：出现明确的无障碍需求，或本地语音模型成熟到零配置可用时。

## 9. 防失控预算（termination 硬停）

- **决策**：不做任务级终止预算（超时/成本硬上限强制终止）。
- **原因**：深度上限 3 + 并发上限 4 已足够防失控；硬停语义（终止后状态处理）复杂且单用户可手动取消（`task_cancel`）。
- **重新评估触发条件**：出现无人值守的长时间自动任务（如夜间批量）且实测失控概率上升时。

## 10. Checkpoint 升级（按 prompt 粒度 + 对话回退）

- **决策**：不升级快照体系到"每次变更自动 checkpoint + 对话一并回退"（Claude Code rewind 形态）。
- **原因**：`capture_workspace_snapshot` 已在每条消息处理前自动调用（ADR-006/008，含 gzip + GC + similar diff）；消息级回退/重做链路完整。按 prompt 粒度 checkpoint 在单用户场景边际价值低。
- **重新评估触发条件**：用户实测需要"回退到任意历史轮次"且现有消息级回退不满足时。

## 11. 执行沙箱（OS 级）

- **决策**：不做 OS 级执行沙箱（bwrap/Seatbelt 类）。
- **原因**：本地单用户信任模型——审批流 + 快照回退已兜底；跨平台（Windows/macOS/Linux）实现成本高。**替代性加固**：命令级审批策略（T2 路线）。
- **重新评估触发条件**：运行不可信代码成为日常（如第三方脚本批量执行）或机器受控审计要求出现时。

## 12. 网络访问策略（默认断网 + 域名 allowlist）

- **决策**：不做网络访问策略引擎（Codex 式默认断网 + 域名白名单）。
- **原因**：同信任模型（见 11）；`web_search`/`web_fetch` 已在审批管控下。
- **重新评估触发条件**：与 11 相同（信任模型变化）。

## 13. 云任务 / 多设备 / 多用户治理

- **决策**：不做云执行、跨设备同步、多用户/企业治理（SAML/RBAC/审计）。
- **原因**：直接违背"本地优先、单用户"定位——这是天演的根本定位约束，不是能力缺口。
- **重新评估触发条件**：产品定位变更（此为定位性否决，触发即定位变化）。

## 14. ACP 控制中心（多 agent 编排平台）

- **决策**：不做 ACP（Agent Client Protocol）多 agent 控制中心（OpenHands Canvas 形态）。
- **原因**：不依赖外部 agent 产品（Claude Code/Codex 等）；内部子任务编排（`delegate_to_agent` + 嵌套深度 3 + 后台任务）已覆盖需求。
- **重新评估触发条件**：用户明确需要同时驱动多个异构 agent 产品时。

## 15. 模型 harness 定制（每模型调优工具集/提示）

- **决策**：不做按模型定制 harness（Cursor 式每模型调优）。
- **原因**：与 2（不做路由）同源——单用户手动选模型的场景下收益有限；维护多套 harness = 持续成本。
- **重新评估触发条件**：与 2 相同。

## 16. git worktree 隔离并行

- **决策**：不做后台任务独立 git worktree 执行。
- **原因**：快照体系（ADR-006/008）是**时间维回退**、worktree 是**空间维隔离**，机制不同不重复；但单用户并发写冲突概率低 + worktree 强制 git 仓库（天演工作区是任意目录，快照体系特意不依赖 git）+ 路径映射/合并复杂度不成比例。现有防线（审批 + 快照回退 + 任务取消）已覆盖主要风险。
- **重新评估触发条件**：出现多后台任务并发写同一文件的实际冲突案例时——届时用**轻量写冲突检测**（任务开始记录文件哈希、完成时检测变化）替代，而非 worktree。

## 17. 全量事件驱动架构（主/子 agent 通信异步化）

- **决策**：agent 间通信保持"同步 await + 消息注入"混合（ADR-013），不做全异步事件总线。
- **原因**：LLM 不是事件消费者（事件必须转成上下文注入 + 触发一轮生成）；单主 agent 单对话下异步运行时收益为零（模型一次只能生成一条思路线）；oh-my-openagent 的 wake 状态机（noReply/shouldReply liveness、activity window、requeue）bug 史证明全异步成本极高。turn 边界消息注入（ADR-013）已获得事件驱动全部收益。
- **重新评估触发条件**：出现多实例平级协作（Agent Teams 形态）或单主 agent 等待期间需响应其他事件的真实需求时——届时先补"任务状态外置 + 统一消息队列"（已具备），再评估聚合器替换。

## 18. 每任务唤醒（后台任务逐个触发主 agent）

- **决策**：唤醒判定 = `allComplete || failure`（ADR-013），部分完成**静默注入**不唤醒。
- **原因**：每任务唤醒产生 N 次 LLM 调用与 UI 打扰；join 信号（`remaining == 0`）已让主 agent 在最终轮看到全部完成消息，汇总信息无缺失。
- **重新评估触发条件**：存在"中间结果需要即时干预"的场景（如长流水线每个阶段都要人工确认）时。
