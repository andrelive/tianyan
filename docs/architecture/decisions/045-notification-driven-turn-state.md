# ADR-045: 纯通知轮状态——移除看门狗，快照携带权威状态

**日期**: 2026-09-26
**状态**: ✅ 已落地
**修订**: ADR-028/029（事件与订阅）之补充；T1-8「流响应看门狗」退场

---

## 背景（2026-09-26 用户实测：长命令被"显式中断"）

前端 `stream-watchdog`（T1-8）以「180s 无任何 `chat_stream` 事件」为判据复位
`streaming/running` 并标记消息中断。其注释假设"前台长工具执行也会喂狗：工具
开始/结果都发事件"——但**执行期间不发**：`execute_command` 等长工具在
`execute_parallel` 里阻塞（实测用户命令 5 分钟级），期间事件流完全静默 →
看门狗在第 180s 把**正常运行**判为中断（复位流状态 + `markLastMessageInterrupted`
+ toast「长时间无响应」）。

更深层的架构问题：**看门狗是用"超时推断"补"通知不可靠"**。而天演的实际部署
形态是 **tauri 同进程内嵌 server**：

| 看门狗在防的故障 | 实际情形 | 结论 |
|---|---|---|
| 后端失联/崩溃（事件永不再来） | server 死 = 应用退出，前端同归；不存在"前端存活但后端失联" | 伪故障 |
| 收尾事件丢失 → UI 永久卡 streaming | 真实存在（有界 broadcast 4096 Lag 丢弃 + SSE 断线期间无重放） | 真缺口——但解法是"能重取"，不是"超时猜" |
| 工具执行期静默 | 正常计算（长命令/大输出） | **误判来源** |

---

## 决策

### 1. 移除看门狗（超时推断退场）

`stream-watchdog.ts` 删除；`chat-stream.ts` 不再喂狗；`use-unified-events`
不再启动看门狗。**前端轮状态只由事件驱动**（后端说 running 就是 running，
直到后端说 idle）——即**纯通知模型**。

### 2. 快照帧携带轮状态权威值（"能重取"的唯一入口）

`/events/subscribe` 的 `snapshot` 帧新增 `turn` 字段：
`{"state":"running"|"idle","auto":bool}`。前端 `applySnapshot` 收到即
`setTurnState`（`idle` 时顺带复位可能残留的 `streamStatus='streaming'`）。

权威来源（**只读查询，不是推断**）：

| 轮类型 | 权威 | 查询 |
|---|---|---|
| 用户轮 | `session_leases` 的 `Stream` 租约在跑 | `stream_active(sid)` |
| 自动轮（唤醒轮/后台轮） | Agent 活动轮槽（`delegation_cancel` 注册表） | `has_active_turn(sid)`（新增，与 `request_cancel` 同源） |

二者互斥（轮锁），`auto` 据此判定。

### 3. 自愈路径收敛为"重取"

任何一次 `onopen`（重连）会重放订阅 → 重推快照 → 轮状态校正；切回会话同理。
收尾事件丢失后的残留状态，由下一次重取消除（不再依赖超时兜底）。

---

## 替代方案与否决理由

| 方案 | 否决理由 |
|------|---------|
| A. 后端在长工具执行期间发心跳 | 心跳是"活性证明"——纯通知模型下不需要证明（状态本来就是后端说的）；且给事件通道增加常态噪音 |
| B. 保留看门狗但豁免"工具执行中"/放大阈值 | 继续维护"猜测逻辑"（需在事件流里重建"是否有工具在跑"的状态机）；阈值永远在"误判"与"发现真挂死"之间妥协 |
| C. 看门狗 + 心跳双保险 | 复杂度最高；本地同进程场景下两者防的是同一件事的更弱版本 |

---

## 后果与残留风险（诚实边界）

**正面**
- 长命令期间状态稳定（不再被误判）、消息不再被错误标记"中断"；
- 状态语义单一（后端权威 + 快照校正），删掉一个模块级定时器与喂狗点。

**残留风险（有意接受）**
- 收尾事件被 Lag 丢弃、且此后该会话再无任何事件、用户也不重连/不切会话 →
  UI 显示"运行中"。缓解：① 重连/切回 → 快照校正；② 「停止」按钮仍可用
  （后端返回 `no_active_stream`）；
- 该模型成立的前提是**同进程内嵌部署**（MSI 形态）。若未来出现"独立 server +
  远程 GUI"部署，应重新评估（届时"失联"成为真实故障模式，本 ADR 需修订）。

---

## 验收

- 前端：`stream-watchdog` 与其测试删除；`applySnapshot` 处理 `turn` 的路径由
  既有快照测试驱动（测试数 −1 = 看门狗测试）；
- 后端：`build_snapshot_payload` 5 参（新增 `turn`），3 处调用点更新；
  `has_active_turn` 权威查询走通（server 176 passed）；
- 行为：长命令（>180s）期间 `turn.state` 恒为 `running`（后端说的），不再复位。
