# ADR-053：上下文自治——模型主动压缩 + 按目标自动续跑

- **状态**：已采纳
- **日期**：2026-11-01
- **相关**：ADR-001（VFS 双层摘要）、ADR-017（演化）、ADR-030（统一 Agent 循环）、ADR-035（会话工作集）、ADR-040（会话排他写）

## 背景

模型对「上下文还剩多少」没有真实感知：它只能从自己见过的消息长度去猜，而压缩触发权完全在系统手里（窗口 × 阈值）。直接后果有三条：

1. **它会把上下文紧张当成"该收工了"的信号**，于是缩小工作范围、少读文件、少跑验证——为了省 token 而敷衍，本末倒置；
2. 系统到阈值会自动压缩，但**压完不会继续**（要等用户或后台任务唤醒），长任务因此在压缩点处"停住"；
3. `goal` 工具虽然提供了"目标"这一层，但没有任何机制**依赖**它——模型没有理由建目标（用户原话：「goal 功能好像没实际用过」）。

## 决策

给模型两只手，并把"继续"的判据交给目标：

### 1. 两个工具

- **`context_status`（只读）**：窗口 / 已用 token（占比）/ 自动压缩阈值 / 临界阈值 / 距阈值余量 / 距压缩点消息数 / 是否具备压缩条件 / 一句结论（hint），顺带给**当前时间**。
- **`compress_context(handoff?)`（写）**：登记一次压缩请求，**调用即收尾本轮**。`handoff` 写「接下来做什么 / 已完成什么 / 注意什么」。

### 2. 压缩必须在轮末做

正在跑的 `AgentLoop` 手里是 `Vec<Message>` 快照；轮内压缩改的是会话链，对它不生效（下一轮请求仍用旧快照 = 白压）。因此工具只**登记**，`AgentLoop` 在工具执行后看到待处理请求就收尾本轮，由 `Agent` 在轮末 `maybe_compress_and_persist(force = true)`。

> 被否决的另一条路：给 `AgentLoop` 加"轮中重载上下文"契约，让压缩后立刻在同一轮继续。改动命中 ADR-030 的循环结构，风险远大于收益；轮边界（几秒）对用户体验是可接受的代价。

### 3. "继续"的判据 = goal 状态（不设次数预算）

压缩成功之后：**本会话有 `active` goal（或未绑会话的全局目标）才自动唤醒**，否则照常结束。

- 用户口径：「把任务完成为止」——按次数/时间卡预算会把长任务截断，与目标冲突；
- 这条把 `goal` 从"可选好习惯"变成"长任务的必备动作"：不建目标 → 压缩后不会被续跑；
- 判据读的是与 `goal` 工具 / REST API **同一份** `GoalStore`（`AgentBuilder::with_goal_store`），传副本会让"刚建的目标压缩后看不见"。

### 4. 保险丝（不是配额）

自旋判据由**模型自己维护**（goal 状态）。它忘了标 `completed`，这条链就没有自然终点，而每轮压缩都要重发一次完整 prompt。因此设一条异常保护：同一条自唤醒链 **60 次 / 1 小时**任一超限即停；用户发新消息重置计数（新任务重新算）。正常任务碰不到。

### 5. 续跑走专用唤醒通道

新增 `TaskWaker::wake_for_continuation`：与 `wake` 同路径，**只去掉「无未消费新消息就跳过」那道过滤**——压缩点由系统写入并立刻标记已消费（`reshape_after_compression`），用"有新消息"当判据会把续跑永远挡在门外。幂等性仍由会话锁保证（`turn_try_lock`）。

### 6. 提示不走 system 前缀

- 系统提示新增一段「上下文与长任务」：**以完成目标为最终判据**、别为省 token 缩小工作范围、需要多轮就先建 `goal`、真紧张就 `compress_context`；
- 占用超过阈值的 80% 时，在**历史消息之后**（与待办摘要同位置）追加一句提示——**不改 system 前缀**：前缀一变，DeepSeek 的前缀缓存全失效（真实成本 + 首包延迟）。

### 7. 可见性

压缩点本身在会话链里可见（分隔符 + 可展开摘要卡片），续跑轮的输出照常流式显示；`/state` 暴露 `usage.session_shown` 等断言面。压缩是**接力**，不是失败。

## 后果

**收益**

- 模型能读真实余量（不再靠猜），且知道有出路——"上下文紧张"不再等于"该收工"；
- 长任务能跨压缩点连续推进，`goal` 有了硬用途；
- 两个工具的取数口径与压缩判定同源（同一个 `prompt_side_tokens()`、同一条"跳过压缩点"规则），不会出现两套数字。

**代价（诚实记账）**

- 每次主动压缩仍是一次完整 prompt 重发（与自动压缩同价）+ 一次唤醒轮；
- 轮边界对用户可见（"这一轮结束 → 新一段开始"），不是无缝续写；
- `handoff` 目前只记日志，**未进摘要 prompt**（需要扩 `ContextPort::compress_for_session` 签名，留作后续）；
- 只给主 agent：子代理的上下文更小、更容易满，但它们走 `task` 会话，需要单独设计一遍。

## 未做 / 后续

2. 子代理的上下文自治；
