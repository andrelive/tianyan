# 工程经验速查（Dev Lessons）

**ID**: `dev-lessons`

**版本**: 1.0.0

**描述**: 跨项目通用工程经验——按"触发场景"组织，遇到对应症状先查这里。

**状态**: 正式

## 适用场景

- "改了代码但行为不变 / 日志无新特征"
- E2E / UI 测试反复失败
- 写数据 / 挂接口前需要核实对方真实形态
- 委派子代理后的结果验证

## 使用说明

### 1. 环境验证（"改动没生效"的第一排查顺序）

**先确认"跑的是哪份代码"，再排查逻辑对不对。**

- 症状：改了代码但行为不变、日志无新特征
- 排查顺序：
  1. **运行产物时间戳 vs 源码修改时间**（exe / jar / class vs 工作区）；
  2. 启动方式是否从缓存 / 仓库解析依赖而非工作区；
  3. 是否有**旧进程残留**（杀父进程后验证端口真的释放：`Get-NetTCPConnection -LocalPort <port>`）；
  4. 桌面应用场景：**进程重启了吗**（安装 / 构建 ≠ 运行中的实例已更新——天演多次遇到"当前实例仍是旧二进制"）。
- 反例：先怀疑业务逻辑、反复读代码，最后才发现跑的是旧产物——浪费最多时间。

### 2. E2E 流程纪律

- **标准场景清单**（每次 UI 改造后必测）：登录 → **刷新直达**（reload 当前页）→ 登出换号（状态是否刷新）→ **深链直达**（直接 URL 进二级页）→ 权限 / 角色差异。
- **快照 ref 跨导航失效**：导航后必须重新 snapshot 再操作，旧 ref 会报 "not found"。
- **框架组件表单注入**：`input.value + dispatchEvent` 对 v-model 不一定生效；优先用工具的 fill 能力。
- **同路径失败 2 次就换路径**：UI 注入失败 → 试 API / CLI / SQL 直改；工具超时 → 换快照 / evaluate / curl 组合。不要在同一条路上耗。

### 3. 数据 / 契约核实（写之前，不凭记忆）

- 跨表 / 跨端写数据前，**核实对方的真实形态**：真实路径 / 前缀（不是"我以为的"）、字段语义（如 `'0'=显示 '1'=隐藏` 这类约定）、列类型与约束。
- "先契约后实现"的另一面：**先扫实现再写契约 / 挂载 / 种子**，双向核实。
- 讨论数据结构 / API 语义 / 框架行为时：**核实规范或源码**，不凭记忆断言。

### 4. 委派 / 代理结果验证

- **代理声称"build 通过" ≠ 运行时正确**：核心转换 / 框架交互逻辑委派后**自己 review 或补单测**，重点验证框架边界（动态 import、路由解析、渲染异常）。
- 子代理报告只作为**线索**，关键事实用一手信息校验（亲自 grep / 读源码 / 跑命令）。

### 5. 收尾纪律

- 调试坑写成"教训 → 规程"沉淀到项目 docs / 记忆；每级验收通过即 commit。
- 教训要**先检索后沉淀**，合并近似条目，避免重复记录。
