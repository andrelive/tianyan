# 方案拷问（Design Grill）

**ID**: `design-grill`

**版本**: 1.0.0

**描述**: 通过逐分支的提问，把方案 / 设计中的每个决策点走透，直到达成共识。

**状态**: 正式

## 适用场景

- 用户想压力测试一个计划 / 设计（"拷问我"、"帮我把方案问透"）
- 动手实现前，把设计树的依赖关系逐条解决
- 评审会上"看起来都对"但没底的时候

## 使用说明

### 核心动作

1. **逐分支追问**计划 / 设计的每个方面，直到**共识**；沿设计树走，**一次解决一个决策间的依赖**；
2. **每个问题都给出你的推荐答案**（不让用户从零思考；推荐 + 理由让判断更快）；
3. **一次只问一个问题**，等反馈再继续；
4. **能查代码回答的问题，就去查代码**（不打扰用户）。

### 配套（grill-with-docs 变体）

- 拷问期间持续对照**既有领域模型与文档**（领域词汇表、ADR、上下文类文档）；
- 当决策结晶时**即时更新文档**（ADR / 术语表）——决策落档，不留在对话里蒸发；
- 术语被拷问澄清后，后续所有讨论用统一词汇。

### 完成判据

- 每个分支要么有明确决策、要么明确"暂不决定 + 触发条件是什么"；
- 决策依赖顺序已解开（不会出现"A 的决策要等 B、B 要等 A"）；
- 落档的决策与对话中的一致。

### 本地实例（天演语境）

- "取消落库"评审即本模式：追问（"未闭合 JSON 怎么办？"）→ 取证 → 修正方案（弃初版改 DSH 对照）→ 决策落文档 / 发布说明；
- 天演 ADR 纪律与"决策即时落档"一致（决策 = 文档，不是聊天记录）。
